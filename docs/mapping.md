# Mapping: Flatcap 2.0 → Gitea 28.2

Role → variable tables. Tables between `build:` markers are generated by `python3 scripts/build.py`; the rest is hand-written.

## How the theme is built

- `src/theme.json` is a versioned copy of the Flatcap 2.0 core and the only source of values. `scripts/build.py` writes no hex by hand: each entry is a role (`{bg.surface}`), a mix of roles in OKLab, or a scale derived from roles.
- Gitea picks a theme from `$GITEA_CUSTOM/public/assets/css/theme-<name>.css`. `[ui] THEMES` lists the names and `DEFAULT_THEME` picks the default. Gitea reads the **last** `gitea-theme-meta-info` block of the file for the display name (`--theme-display-name`) and the scheme (`--theme-color-scheme`). Dark themes set `--is-dark-theme: true`. The auto theme wraps a light and a dark `:root` block in `prefers-color-scheme` media queries and carries one meta block at the end. (Source and docs of 28.2.0: `services/webtheme/webtheme.go`, `web_src/css/themes/theme-gitea-*.css`.)
- Gitea loads the theme stylesheet **after** `index.css`, so values set in `:root` and the two override rules win at equal specificity.
- A custom theme replaces the built-in one; a variable it does not set is undefined, not Gitea's default. So all 294 theme variables of 28.2.0 are set in both modes ([inventory](inventory.md)), plus four font and radius variables that live in `index.css` and are overridden here.

### Decisions worth knowing

- **Shared roles.** Gitea reuses a few variables for several jobs. `--color-white` is the text on every colored fill (red and green buttons, colored labels, toggle knobs, the selection color); it is set to `accent.on`, so in Slate it is dark text on pastel fills and in Daylight light text on deep fills. The named colors (`--color-red`, `--color-green`…) are fills **and** text, so they come from the feedback foregrounds (`danger.fg`, `success.fg`…), which meet 5:1 on the surfaces and 4.5:1 with `accent.on`.
- **Primary scale.** `primary-dark-N` moves toward the strongest text, `primary-light-N` toward the page background, as in Gitea. `primary-light-4/-5` carry `--color-primary-contrast` text (review counter), so the scale stops at 4.6:1 with `accent.on`; this compresses the activity heatmap's low end, which stays sequential (checked below). Hover and pressed use `accent.hover` and `accent.pressed` directly (Gitea derives them from the scale).
- **Borders.** `--color-secondary` (128 uses) is `border.subtle`: separators are decorative because surfaces already separate. Buttons, selects, inputs, checkboxes and toggle tracks use `border.control` (3:1).
- **Diff.** Rows are the feedback backgrounds. The word highlight is the strongest step toward the feedback foreground that keeps every code token at 4.5:1 and primary text at 7:1, so it is a gentle step (the `+`/`−` signs and row tint carry the meaning, not the word highlight alone). Moved lines use the info tone.
- **Syntax.** Keywords, functions, strings, numbers, types and comments use the six `syntax.*` roles; variables, operators, punctuation and namespaces stay neutral text. Invalid input and tracebacks use `danger.fg`.
- **Selection and focus** are the only CSS rules, because Gitea has no variable for either: selection uses `selection.bg`/`selection.fg` instead of `--color-primary-light-1`/`--color-white`, and the focus ring uses `focus.ring` with the core's width and offset, drawn outside the control so it is measured against the surface (Gitea draws it inside with `--color-primary`).
- **Radii and fonts.** Gitea exposes `--border-radius` and `--border-radius-medium`, set to `radius.control` and `radius.panel`. Some Fomantic rules hard-code `.28571429rem`; those keep it. Fonts come from `--fonts-proportional` and `--fonts-monospace`; the code view size (12px) is hard-coded by Gitea and is not changed.
- **No glow, gradients or blur.** None is set. `--color-shadow` is the core's overlay shadow color; Gitea draws it on menus and modals.
- **Brand marks.** `--color-logo` and `--color-git` are monochrome roles (accent and secondary text) instead of Gitea green and Git orange.

## Limitations

- **Colors Gitea does not take from the theme:** user-defined issue label colors (Gitea picks black or white text by luminance), the repository language bar and dots, file-type icons (Material icon set), avatars, the Gitea and Git logos shipped as images, emoji, and native browser controls (checkbox UA text, scrollbars follow `color-scheme`).
- **Shared variables.** Because `--color-white` is `accent.on`, anything in your own custom CSS that expects it to be white will differ. Named colors in Slate are pastel fills with dark text.
- **Diff word highlight** is subtle by design: raising it would drop code tokens below 4.5:1.
- **Heatmap.** The activity graph reads `primary-light-4 … primary-dark-4`; the low end is not as dark (Slate) or light (Daylight) as in Gitea because of the 4.6:1 constraint above. It remains sequential.
- **Chart series beyond 16** use Gitea's own colors.
- **Updates.** Gitea reads theme files into memory in production mode; restart after changing a file.

## Rebuilding

```sh
python3 scripts/build.py --check      # validate names, contrast and that generated files are current
python3 scripts/build.py              # regenerate themes/*.css and the doc blocks
python3 scripts/build.py --sync       # refresh src/theme.json from ../00-Flatcap
python3 scripts/build.py --contrast   # print every measured pair

# Rebuild the inventory from a running Gitea of the target release (a throwaway container is enough):
python3 scripts/inventory.py --fetch http://127.0.0.1:3000 /tmp/gitea-assets
python3 scripts/inventory.py --extract /tmp/gitea-assets   # rewrite src/gitea-inventory.json
python3 scripts/inventory.py --check /tmp/gitea-assets     # fail if the stored inventory differs
```

Python 3.10+, standard library only.
